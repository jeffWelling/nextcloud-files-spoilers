# Nextcloud File Spoilers - Claude Code Documentation

## Overview

**File Spoilers** is a Nextcloud app that hides file previews (thumbnails) for files with configurable label triggers. Instead of showing the actual preview, a placeholder is displayed until the user clicks to reveal it.

**Primary use cases:**
- Hide sensitive photos from being visible while scrolling
- Prevent shoulder-surfing in public places
- Spoiler warnings for media content

## Critical Dependency

**REQUIRES**: The `files_labels` app must be installed and enabled. This app integrates with files_labels to read file labels and determine which files should be spoilered.

## Architecture

### Frontend (JavaScript)

**Main file: `src/main.js`**

This is the core of the app's functionality. It runs in the Files app and:

1. **Loads user settings** from the API (`trigger_labels`, `placeholder_file_id`)
2. **Watches for file rows** using MutationObserver to detect new files appearing in the DOM
3. **Fetches labels** from files_labels app API (with batching and caching for performance)
4. **Checks if file matches trigger** (e.g., `sensitive=true`)
5. **Applies spoiler placeholder** by:
   - Hiding original preview content
   - Injecting a placeholder div with either custom image or default eye-off SVG
   - Adding click/keyboard handlers to reveal
6. **Listens for label changes** via Nextcloud event bus (`files_labels:label-changed`)
7. **Updates spoilers in real-time** when labels change

**Key data structures:**
```javascript
spoilerState = {
  settings: { trigger_labels, placeholder_file_id },
  labelCache: Map(),        // fileId -> labels (prevents duplicate API calls)
  revealedFiles: Set(),     // Tracks which files user has revealed this session
  loaded: boolean,
  pendingPromises: Map(),   // Deduplicates concurrent label fetches
}
```

**Settings UI: `src/views/PersonalSettings.vue`**

Vue component that provides:
- List of configured trigger labels (with add/remove)
- Input validation for label format `[a-z0-9_:.-]+=.+`
- Custom placeholder image selector (currently uses prompt, needs proper file picker)
- Success/error notifications

### Backend (PHP)

**Service Layer: `lib/Service/SpoilerService.php`**

Core business logic:
- `getSettings()` - Retrieve user's trigger labels and placeholder file ID
- `setTriggerLabels(array)` - Save trigger labels (with validation)
- `setPlaceholderFileId(int)` - Set custom placeholder image (validates file exists and is image)
- `isSpoilered(array $fileLabels)` - Check if file labels match any trigger
- `checkBulkSpoilerStatus(array)` - Batch check multiple files

Settings stored in `oc_preferences` table per-user:
- Key: `trigger_labels` (JSON array of "key=value" strings)
- Key: `placeholder_file_id` (integer file ID or null)

**Controllers:**

1. **SettingsController** (`lib/Controller/SettingsController.php`)
   - OCS API endpoints for managing user settings
   - Routes: `/api/v1/settings`, `/api/v1/settings/trigger-labels`, `/api/v1/settings/placeholder`

2. **SpoilerController** (`lib/Controller/SpoilerController.php`)
   - OCS API endpoints for checking spoiler status
   - Integrates with files_labels `LabelsService` to fetch file labels
   - Routes: `/api/v1/spoiler/{fileId}`, `/api/v1/spoiler/bulk`
   - **Note**: Currently not used by frontend (frontend calls files_labels API directly)

## API Endpoints

All endpoints are OCS API (prefix: `/ocs/v2.php/apps/files_spoilers/api/v1/`)

### Settings API

```bash
# Get current settings
GET /settings
Response: { trigger_labels: string[], placeholder_file_id: int|null }

# Update trigger labels
PUT /settings/trigger-labels
Body: { labels: ["sensitive=true", "nsfw=yes"] }

# Set custom placeholder image
PUT /settings/placeholder
Body: { fileId: 12345 }

# Remove custom placeholder (use default)
DELETE /settings/placeholder
```

### Spoiler Check API (optional, not used by frontend)

```bash
# Check single file
GET /spoiler/{fileId}
Response: { fileId, spoilered: boolean, labels: object }

# Check multiple files
POST /spoiler/bulk
Body: { fileIds: [123, 456, 789] }
Response: { files: { 123: true, 456: false, 789: true } }
```

### Testing Label Matching Logic

The frontend uses this logic (in `main.js`):
```javascript
function isSpoilered(fileLabels, triggerLabels) {
  for (const trigger of triggerLabels) {
    const [key, value] = trigger.split('=')
    if (fileLabels[key] === value) return true
  }
  return false
}
```

The backend uses similar logic in `SpoilerService::isSpoilered()`.

## Important Implementation Details

### Performance Optimizations

1. **Label caching**: Labels are cached in `spoilerState.labelCache` Map to avoid repeated API calls
2. **Batch fetching**: Multiple label requests are batched together with 50ms delay
3. **Deduplication**: Concurrent requests for the same file are deduplicated via `pendingPromises`
4. **DOM checked flag**: Previews have `data-spoiler-checked="true"` to prevent re-processing

### Event Bus Integration

The app subscribes to label change events from files_labels:
```javascript
subscribe('files_labels:label-changed', handleLabelChange)
```

This enables real-time updates when labels are added/removed.

### DOM Selectors

The app searches for file rows using multiple selectors for compatibility:
```javascript
'.files-list__row, [data-cy-files-list-row], .file-row, tr[data-file]'
```

Preview containers:
```javascript
'.files-list__row-icon, .files-list__row-icon-preview, [data-cy-files-list-row-icon]'
```

### Session-Only Reveals

When a user clicks to reveal a spoiler, the file ID is added to `spoilerState.revealedFiles` Set. This persists for the browser session (until page reload) but is not saved to the server.

## Gotchas & Considerations

1. **files_labels dependency**: App will gracefully degrade if files_labels is disabled (no files spoilered, no errors)

2. **Placeholder file access**: Custom placeholder must be accessible to the user. If the file is deleted, browser will show broken image. The app doesn't auto-clear invalid placeholder file IDs.

3. **Vue component not used**: `src/components/SpoilerPlaceholder.vue` exists but is NOT currently used. Spoiler placeholders are created as plain DOM elements in `main.js` for simplicity.

4. **File picker UI**: Custom placeholder currently uses browser `prompt()` to get file ID. Should integrate with Nextcloud file picker component for better UX.

5. **Cross-tab state**: Revealed files state does NOT sync across browser tabs. Each tab maintains its own revealed set.

6. **Double-click vs single-click**: The SpoilerPlaceholder.vue component uses double-click, but main.js uses single-click. Main.js behavior is what's actually deployed.

7. **Label format restrictions**: Only lowercase letters, numbers, and `_:.-` characters allowed in label keys (enforced by regex validation)

8. **OR logic for triggers**: If ANY configured trigger matches, the file is spoilered. No AND logic support.

9. **Webpack output path**: Built files go to `js/` directory, which is gitignored. Must rebuild after pulling changes.

10. **Initial state provider**: Settings are injected into the page via Nextcloud's `IInitialState` service in `Personal.php`, then loaded in Vue with `loadState()`.

## Security Considerations

- User settings are stored per-user and cannot be accessed by other users
- Custom placeholder file ID is validated to ensure user has access to the file
- Only image files can be used as custom placeholders
- Label matching is done client-side, so sensitive label data may be visible in API responses
- No privilege escalation risk - users can only spoiler files they can already see

## Files_labels Integration Points

The app integrates with files_labels at these points:

1. **Frontend label fetching**:
   - Bulk endpoint: `/apps/files_labels/api/v1/labels/bulk` (POST with fileIds array)
   - Single endpoint: `/apps/files_labels/api/v1/labels/{fileId}` (GET, fallback)

2. **Backend label fetching** (optional):
   - Direct service integration: `\OCA\FilesLabels\Service\LabelsService::getLabels(fileId)`
   - Bulk method: `\OCA\FilesLabels\Service\LabelsService::getLabelsForFiles(fileIds)`

3. **Event bus**:
   - Listens for: `files_labels:label-changed` event with `{ fileId, labels }`
